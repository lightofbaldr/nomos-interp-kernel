# LAB on the Pi Substrate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run Harness² on LAB (harvey-labs legal tasks) with Pi as the executor and the LAB judge served by the CLI bridge, end to end on one task.

**Architecture:** A first-party runner `harness2/benchmarks/lab_pi_runner.py` (stdlib + harness2 only, so it is unit-testable and runs under harness2's own Python) stages a LAB workspace, loads LAB's base skills and the rendered harness into Pi through explicit paths, runs `pi --mode json` with the runtime guard, resumes the session for the continue-nudge, and writes the `results/<run_id>/{output, pi_session.jsonl, metrics.json}` layout that `evaluation.run_eval` scores unchanged. The LAB adapter gains a `pi` cell; the shipped LAB judge patch gains a `cli/` provider that talks to `harness2-judge-bridge` through the Responses API.

**Tech Stack:** Python 3.12 stdlib, `unittest`, Pi 1.3.0, the LAB venv (`dependencies/harvey-labs/.venv`) for document parsing and judging, pandoc 3.1.3 and poppler already installed.

**Spec:** `docs/superpowers/specs/2026-10-20-pi-substrate-cli-improver-judge-design.md` (section 4.5 LAB, 4.4 judge bridge wiring)

## Global Constraints

- Everything in the first plan's Global Constraints still holds: Python `>=3.12,<3.14`, no new runtime dependencies, ruff clean, `unittest` modules under `tests/`, commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`, local commits only.
- LAB is already installed at the pinned commit (`harness2-setup lab --substrate pi` ran on 2026-10-20; `dependencies/harvey-labs/.venv` has pandas, pdfplumber, markitdown; `opencode/scripts/read_doc.py --in host` parses a `.docx`).
- Results layout and names are fixed by upstream: `results/<run_id>/workspace/`, `results/<run_id>/output/` (graded), `metrics.json` written last, `scores.json` written by `evaluation.run_eval`; the run dir is passed to the evaluator as an absolute path.
- Judge model ids stay `cli/claude:<model>` / `cli/codex:<model>`; `config.LAB_JUDGE_MODEL` passes a `cli/` id through unchanged.
- "A judge or runner failure is `None`, never a zero, and never cached as complete" holds: no `metrics.json` when the Pi stream had no parseable events; `scores.json` only from the judge.
- The vendored patch `third_party/patches/harvey-labs-judge-vertex-anthropic.diff` is a release asset: `dependencies/ASSETS.json` carries its sha256 and `scripts/check_provenance.py` must pass after it changes.

## Review Focus

1. A rollout whose Pi stream has no parseable events (dead provider, auth failure) must leave no `metrics.json`, so the adapter raises and never caches it. Pinned by `test_run_task_without_events_writes_no_metrics` (Task 3).
2. A harness skill named like a LAB base skill (`docx`, `pptx`, `xlsx`) must be rejected at validation: Pi keeps the first discovered skill and only warns. Pinned by `test_validate_pi_rejects_base_skill_name` (Task 4).
3. The runtime's `read_doc.py` must win over anything the harness ships, and `pack.py`/`unpack.py` stay reserved. Pinned by `test_stage_workspace_runtime_read_doc_wins` (Task 3) and the existing reserved-script validation.
4. The continue-nudge must stop when deliverables exist and the final text is `DONE`, must not run without a session file, and must never exceed `--max-continue`. Pinned by `test_nudge_loop_stops_on_done` and `test_nudge_loop_skipped_without_session` (Task 3).
5. `cli/claude:sonnet` must reach the LAB judge unchanged and route to the bridge. Pinned by `test_lab_judge_model_passthrough` and `test_patched_judge_routes_cli_prefix` (Task 2).

  - `def run_task(args) -> int`: writes `config.json`; first invocation with the task prompt; up to `--max-continue` resumes with `NUDGE` while a session file exists, wall time remains (≥ 60 s), and not (deliverables exist and `final_message` is `DONE`), stopping when a resume adds no tool calls; harvests `workspace/output` → `output/`; `metrics.json` LAST with `runner="pi"`, `model`, `task`, `run_id`, `turn_count`, `tool_calls`, `input_tokens`, `output_tokens`, `reasoning_tokens`, `total_tokens`, `wall_clock_seconds`, `cost_usd`, `finished_cleanly`, `exit_code`, `documents_read`, `total_documents`, `harness_components`, `completed_at`; returns 2 and writes no `metrics.json` when `parse_events` finds nothing; returns 1 when rc was 0 but nothing was delivered.
