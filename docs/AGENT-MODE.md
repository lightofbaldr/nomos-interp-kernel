# Chat Agent mode

Review branch only. No merge, deployment, live-lab restart or existing
conversation-data mutation is part of this change.

From Chat, select **Agent mode**. It is off by default. The server serializes
configuration against generation, runs the existing file-isolation and Mojo
toolchain probes, enables file tools plus fixed-argv Mojo, turns on available
emotion/workspace readouts, and selects the Agent run budget. A failed probe
does not enable tools. The current harness and steering are preserved.

The adjacent **Harness & files** pane shows current provenance, bounded file
previews and attributed workspace readouts. **Configure harness & budget**
offers the base instructions, saved imported revisions, fork and the existing
import editor. Applying a revision restores its tool selection too; check the
mode afterward. A fork has an empty workspace. The ordinary switch never adds
a shell. Switching it off clears tools but leaves saved readouts available.

## Budget and signals

- Chat: 6,144 requested output tokens per request, unchanged.
- Agent: 8,192 requested output tokens/request, at most 32 model requests and
  64 tool calls, and a 20-minute entire-run deadline.
- The server owns the ledger and abort signal across tool follow-ups. Every
  request and tool is charged before work. Recovery cannot reset it; Stop is
  explicit. Profile changes do not rewrite the running ledger.
- The serve may shorten output to fit context. New turn labels say requested;
  any derived context-shortened ceiling is labelled separately. Missing
  effective-limit evidence is unknown. See AGENT-BUDGET-READOUT-AUDIT.md.
- Readouts remain keyed to their real request/task/position during tool calls.
  Follow mode can retain the preceding measured request while the next one
  has only prompt rows. Explicit selection never borrows another request.
  Partial/failed readouts stay partial/failed. Tool output and projections are
  not correctness or honesty scores.

## Files boundary

`GET /api/pi/files` accepts only an existing conversation, then a server-issued
snapshot and entry ID. The browser never supplies a filesystem path. The root
is the existing session DB's private workspace tree. Viewing creates no files
or conversations. All components are descriptor-walked, no-follow; mounts,
hardlinks, symlinks, special files and unsafe entries refuse or are omitted.

Listings are bounded to 128 returned files, 512 inspected entries, eight
directory levels, 4 MiB aggregate text and two seconds. Text previews are at
most 256 KiB, UTF-8 only, escaped and never executed. The read rechecks both
snapshot identity and the actual object before and after. Refresh occurs on
durable tool-result events, not every streamed token. Listings may be partial;
omissions and stale/unavailable previews are explicit.

Same-origin loopback protections, purge maintenance leases, fixed runtime
paths and no-store responses are retained. This remains a private local app,
not multi-user authentication or a public agent service.

## Harness delivery

Imports remain the existing pinned text/profile subset, with inline skills.
Scripts are not copied and model extensions are not loaded into the host.
The improved rehearsal's `mojo-verify-note.ts` is therefore not active. A
script-only, hashed dual-path helper import is a separately deferred schema
change under Prime 1716; no unmodified Harness²-executor claim is made.

## Verification

Node 24.22.1. `node scripts/agent-regression.mjs` builds first and runs the
application units, real CPU sandbox controls and browser suites. It never
runs a real model or paid API. `agent-tests.mjs` checks integration and durable
budgets; `agent-workspace-tests.mjs` adds strict typechecking and filesystem
controls. Desktop/mobile screenshots are generated by `agent-browser.mjs`
under `preview/checks/` and are synthetic, not live model results.

`agent-budget-e2e.mjs --live` is a separate explicit, coordinated laptop test.
Its two fresh conversations and all artifacts go to an exclusive evidence
directory. `--fixture` exercises the same checker against a synthetic model
and real CPU compiler. The counter requires an operator-private manifest in
the documented shape in `agent-prompt-count.py`. No automatic retries or
serve restarts. Do not run it merely because the regular suite passes.
