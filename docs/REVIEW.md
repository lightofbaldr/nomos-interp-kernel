# Frontend review

## Direction

An actual chat application, not a hackathon landing page or dense research dashboard. Conversation and composition are primary. A separate inspector answers “what did this probe report here?” without turning that answer into “the model is safe.” Dark, near-neutral surfaces and restrained Muse-inspired blue; self-hosted Geist for conversation, Geist Mono only for coordinates and metadata. No official Meta logo or brand-compliance claim.

Adam's supplied Muse mascot now sits as a static, low-opacity watermark behind the conversation only. The image-editing skill produced a transparent cutout without the supplied wordmark/background; its source, selected PNG and exact prompt are preserved in `docs/assets/`. A 240,774-byte local WebP retains transparency. The artwork is decorative, cannot intercept clicks, is excluded from the accessibility tree and does not change with emotion/probe state. Contrast checks include a conservative all-white pixel at the watermark's CSS opacity, rather than ignoring the image backdrop.

The model title uses the local Svelte Magic `SparklesText` component with four small blue/pale-blue stars and scoped typography. Click the title to pause/resume; native keyboard activation works. Reduced-motion preference changes unmount the running effect, and hidden tabs also unmount it. The title remains static/readable during SSR and reduced motion. It is decorative branding, never a generation or safety-status indicator. The shared animation library was not changed.

The emotion-steering Dock sits below the composer, not over the transcript. The actual local Magic Dock gives a restrained desktop proximity spring; Bits UI Toggle/Tooltip supplies pressed state, keyboard activation and informative labels. Joy, Calm, Sadness, Fear, Anger, Desperation and Compassion have visible names, 60px targets and blue/checkmarked selection. Desperation uses a distressed/melting face and Compassion a hand-and-heart; these are intent labels, not learned model capabilities. The seven choices wrap into two rows at widths up to 576px instead of shrinking hit targets or hiding controls. Independent selections persist through chat, replay and source changes until turned off or cleared; reload defaults to all off. Narrow/coarse-pointer and reduced-motion modes use a static Dock. Motion-mode subtree recreation preserves selection while cancelling magnification. No new dependency or shared-library edit was needed.

Hallmark's Workbench shape informed the application framing and restraint. Its marketing-specific hero/footer rules are not imposed on a chat surface. The local Svelte component skills informed ordinary imports, explicit callbacks and reduced-motion fallbacks; no registry JSON or browser custom elements. The completion skill led to the observable gates in `GATES.md`, including viewport bounds rather than merely CSS visibility.

## What the browser can actually do

- Compose a local message with Enter/Shift+Enter, stop a scripted response and select conversations.
- Open/close inspection, freeze a frame while replay continues, resume following, scrub exact frames and select layers.
- Import a bounded, validated trace; export the trace without upgrading its provenance.
- Switch to a disconnected state with no fixture readouts and no enabled model submission.
- Open keyboard-managed dialogs/tabs; phone inspection is a modal sheet, not an overlay that initially covers the chat.
- Select independent emotion-target previews, turn each off or clear all, without changing answers, readouts or trace exports. Selection is UI intent, not acknowledged steering.

Live mode now has real multi-turn model context, provider reasoning and answer streams, cancellation and measured KV counters through a fixed same-origin proxy. Demo/recorded traces still represent one user/assistant pair. Live history is bounded and in-memory, including stopped partial replies; reload, New conversation or leaving live mode clears it. There are no accounts, persisted chats, tools, attachments or public authentication. “Production chat feel” is not a deployment-readiness claim.

## Scientific and safety boundary

Demo data, text, scores, layers, positions and replay timing are synthetic. Configured live mode opens blank and shows actual chat/health/counters, with workspace/emotion values unavailable. Source labels remain explicit. Recorded values are signed cosine scores, not probabilities; live stream chunks are never made into fake inspection frames or token counts. The Dock always displays “Not applied · kernel steering is not connected.” It previews targets only; no actual steering, risk mapping, safety score or enforcement is included. Active styling describes selection, never an observed emotional state or proven effect. Multiple-target composition and intervention strength remain backend decisions.

An imported file remains unverified regardless of its hash. The UI says “Kernel hash,” not “Loaded kernel”: a self-reported field cannot attest the serving process. A concept diagram's connecting strokes are layout, not measured causal relationships. Emotion-concept signals do not establish subjective feelings; workspace projections are not a complete thought transcript. Missing data is explicitly unmeasured/unknown, never silently zero.

The inspection file contract remains a proposal, not an approved kernel telemetry protocol. Chat and KV use the implemented serving contract. Actual provider reasoning stays on, remains separate from answer content and is retained byte-for-byte for follow-ups. The local AI Elements Reasoning Root/Trigger is composed with a Bits Collapsible plain-text body, avoiding model-authored HTML/Markdown execution. The fixed system prompt prevents date churn from throwing away a KV prefix.

## Verification and repaired defects

The command oracles and current fingerprints live in `GATES.md`; browser observations and screenshots are under `preview/`. The type/build oracle requires zero errors and warnings. Contract controls reject malformed identities, dimensions, scores, ordering, provenance claims and prototype-pollution fields. Browser controls test cancellation, source separation, trace import/export and inert markup, plus latched Dock selections, keyboard toggles, clear-all, reload-off and strict non-application. The steering negative control verifies both unchanged displayed answer/readouts and a complete unchanged exported fixture, not just one score. UI checks cover seven viewport widths, laptop-height bounds, 60px Dock targets, full label fit, two-row phone layout, selection of both new targets, hover magnification/return, keyboard tooltips, and reduced/normal motion including preference changes. These are frontend checks, not kernel steering tests.

Two negative controls mattered during review. A CSS-only “visible” composer test passed while the actual laptop composer was below the viewport. Bounding-box checks failed on the bad layout; a constrained grid track and independently scrolling bodies fixed it. Computed contrast caught faint text at 4.387:1 on the composer surface; a brighter faint-text token fixed it. The contrast script checks nine actual rendered states, including selected Dock/tooltip text, plus neutral-surface/focus/accent-ink pairs. It is not an exhaustive accessibility certificate: disabled text, icon geometry, pseudo-background compositing and transient animation opacity are explicitly outside that oracle.

The local preview restart helper validates the exact owned tmux pane, process working directory, executable/arguments and loopback environment. A stopped session may be recreated only on a vacant port, followed by an owned-process check; no unrelated listener is killed. The live browser gate checks the served manifest and entry bytes against the current build, not just a successful page response. Only this UI preview is restarted; other previews and model services are untouched. This bring-up caught the preview stopping during rebuild; the missing-session guard failed closed before the vacant-port recovery was added.

## Security, performance and release limits

Trace inputs remain client-local plain data bounded to 2 MB. Message/reasoning/label markup is escaped rather than executed. Live prompts and exact conversation history are sent through a same-origin proxy only to the server-configured kernel. The browser cannot choose a URL. Origin checks, JSON/body/history limits, upstream timeouts and cancellation are implemented, but are not authentication or a full server-hardening review. No provider keys, external assets, public deployment or model service changes were introduced.

This is not a full security audit. The 2026-10-13 npm audit reported 16 low-severity dependency-tree entries, no moderate/high/critical entries. Those counts include transitive advisories propagated to parent packages, not sixteen independently demonstrated exploit paths. No forced major upgrades were applied to shared libraries. The install audit is not proof that the app is secure.

Browser checks use headless Chromium with browser GPU disabled. Transport/chat failure controls run against an isolated CPU-only fake kernel; the separately labelled kernel-chat acceptance sends a bounded real request to Adam's already-running model. The fake backend verifies exact reasoning/answer history, fixed system prompt, UTF-8/CRLF fragmentation, Stop propagation, no stats polling during generation, malformed/early-ended streams and offline behavior. A real Paris/reasoning/stop check is integration evidence, not a losslessness, model-quality or safety gate. Before public deployment: add authentication/rate limits, durable history/recovery, real probe contracts and outcome-based safety tests, and review dependencies/accessibility/monitoring separately.

Before the mascot addition, Lighthouse 13.5 on the local preview measured desktop performance/accessibility/best-practices 100/100/100 (LCP 0.5 s, CLS 0.004, TBT 0 ms); default simulated mobile 97/100/100 (LCP 2.3 s, CLS 0, TBT 20 ms). The audit caught decorative Phosphor icons exposed as unlabeled images and a wordmark label mismatch; those were repaired and re-measured. Those figures are historical pre-mascot observations, not a performance measurement of the new image or title effect. These automated accessibility scores are not a complete WCAG conformance claim.
